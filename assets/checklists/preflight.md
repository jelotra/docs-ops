# 交付前清单（preflight）

> 本清单是 je-docs-ops 自带的通用最小规范，从模板起稿的每份正文文档交付前逐项自检。
> 不依赖任何外部 skill；机器可检项由 `python scripts/je-docs-ops.py check --project <项目>` 兜底。

## A. 正文规则（n02，机器可检）

- [ ] 现在时写作：只描述当前机制，不含具体日期、需求号 / 轮次编号。
- [ ] 无过去时措辞：不含「已交付 / 本轮 / 首轮 / 上轮 / 上次交付 / 当前基线 / 51 passed」等时点计数（引用块 `>` 的元说明除外）。
- [ ] 无时点数字：测试数、覆盖率等会过期的值不写进活文档。
- [ ] 历史跳转位：正文含指向历史档案的相对链接；演变只留一句跳转，不复制历史内容。
- [ ] 结构合规：`check` 输出 `structure=passed`（allowedDirs / historyLink / bodyPast / historyIndex 全绿）。

## B. 分层与归档（n01 / n03）

- [ ] 会过期的内容进历史层，不会过期的留在正文。
- [ ] 旧文档改造先 `git mv` 归档再重写，git rename 可追溯。
- [ ] 历史层有 `README.md` 索引，每份档案登记一行；归档文件只进不改。

## C. 残留门禁（n04，机器可检）

- [ ] `residue.rules.json` 已就位（缺失先 `residue --mint --project <项目>`）。
- [ ] 四类检测通过：`patterns`（旧名）、`dirLists`（清单实存）、`deadLinks`（相对死链）、`generatedDrift`（生成物漂移，按需 `--generated`）。
- [ ] `check` 输出 `residue=passed`，退出码 0（0 通过 / 1 违规 / 2 配置错误）。

## D. 通用最小格式（内建，不依赖外部）

- [ ] 标题与正文用中文；英文仅限代码符号 / API / 枚举 / 标准缩写。
- [ ] 表格单元格短值短判定；列数 >8 时拆分。
- [ ] 文件与目录名全小写 kebab-case；文件名建议 ≤30 字符。
- [ ] 引用一律可点击：本地用相对路径 + 稳定锚点，不用纯文本路径承载跳转。
- [ ] 示例用 `<占位符>`，不写真实路径与真实数值。

> 深度格式 lint（emoji 词表、超宽表格自动检测等）属可选增强，可由 `document-governance` 提供；本清单与上述机器检查已覆盖通用文档场景的最小必需项。
