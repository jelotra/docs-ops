# 归档流程：先 git mv 归档再重写

> **何时进入**：旧文档改造（正文混历史、roadmap 过长、内容整体过时）需要「保留事实 + 重写正文」时。
> **离开条件**：原文经 `git mv` 进入历史层且索引登记；新正文上线；门禁通过。

## 输入

- 待改造文档路径。
- `python scripts/docs-ops.py migrate --file <旧文档>` 输出的操作清单（哪些行含历史措辞、归档目标路径）。

## 怎么做

1. **生成迁移计划**：跑 `migrate`，它按过去时措辞启发式列出「建议随原文归档的行」与 `git mv` 目标路径。
2. **先归档**：`git mv docs/x.md docs/history/x-archive.md`——**必须先归档再重写**，保证 git rename 检测成立、对比事实零丢失；禁止「复制内容后删除原文件」。
3. **再重写**：在原路径用 n02 的模板起稿，只写当前是什么；历史细节一律链接到归档文件。
4. **登记索引**：历史层 `README.md` 索引表追加一行（档案、内容、归档原因）。
5. **跑门禁**：`python scripts/docs-ops.py check --project <项目>`（结构 + 残留两项全绿才算完成）。

## 产出

- 归档文件（git rename 可追溯）+ 更新的历史索引 + 重写后的正文。
- 门禁证据：`check` 输出 `structure=passed residue=passed`。

## 边界

- 归档文件**只进不改**：修正以追加注记呈现，不改写原文。
- 本流程不做语义级内容评审（哪些事实值得保留属人工判断），启发式清单只是辅助。
- 一次迁移一个主题；不要把不相关文档的历史塞进同一份档案。
